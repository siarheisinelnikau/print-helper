# Architecture

## Document model

`layout.rs` contains a serializable project recipe: explicit format version, paper settings and ordered page records. Source records contain canonical paths, SHA-256, source page index and native dimensions in points. Crops are fractions of original edges, followed by clockwise quarter turns. N-up cells are row-major. A single `fit` calculation centers each page inside a cell without changing aspect ratio. All margins and gaps are in millimeters, converted through 72 PDF points per inch.

`document.rs` owns immutable image/Windows PDF sources. It bounds actual file reads, rejects oversized files/images, applies EXIF orientation, composites alpha over white and validates saved recipes against source hashes/dimensions. Images are cropped in original pixels before any resampling. Fractional image boundaries expand to the nearest enclosing source pixels to keep tiny crops nonempty. PDFs are loaded from in-memory streams; sources are never opened for writing. Windows PDF sizes are in 96-DPI device-independent units and are converted to points with a 0.75 factor. PDF render requests account for crop before selecting the full-source bitmap dimensions and enforce a raster budget before entering WinRT. The native engine's default page background is white.

`output.rs` creates sheets through one common rasterizer. Preview requests a roughly 1000-pixel longest edge; export/print select 150/300 DPI. Each sheet is generated independently. A minimal PDF 1.4 writer stores sheets as losslessly deflated RGB Image XObjects, includes explicit MediaBox dimensions and a complete xref table, and retains at most one sheet's image/compression data. Files are written to unique adjacent temporary files and flushed before Windows MoveFileEx without REPLACE_EXISTING publishes them. Existing source/output files survive save failures and cancellation. The non-Windows library fallback uses no-overwrite hard links; the application is supported on Windows only.

`printing.rs` opens PrintDlgW only for an explicit Print action. It checks physical dimensions against the layout (six-point tolerance) and driver hard margins before StartDocW. It draws top-down 32-bit DIBs to the physical paper coordinate system, offsetting the printable-area origin, and releases HDC/global dialog resources through RAII. Failures/cancellation call AbortDoc for the current job. Driver copies/collation use PD_USEDEVMODECOPIESANDCOLLATE. No printer or system defaults are changed by the app directly. Driver-specific dialog and spooler effects require manual testing.

## UI and work lifecycle

`main.rs` constructs the egui interface independently of a GPU framework. `native.rs` hosts it with winit 0.30.13 and egui-winit 0.33.3. Input, IME, clipboard, cursor, URLs, DPI information and root viewport commands use egui-winit. The supported application has one native window with embedded egui dialogs; it does not expose secondary native viewports or native screenshot commands. The page list is virtualized. Preview revisions discard stale results; undo/redo keep 64 recipe snapshots and the thumbnail cache is capped at 600 textures.

Two persistent workers use two-slot command and four-event bounded queues. Each dispatcher accepts at most one background render and one explicit action; an action can wait behind a render without being silently dropped. Foreground work keeps controls disabled until its own Finished event, independently of the preceding preview's completion. Cancellation/close skips queued work before it can open a dialog. `BackgroundWake` coalesces independent event-loop notifications, so results and explicit shutdown commands remain deliverable while no egui frames run. This avoids relying on egui's already-pending repaint flag while hidden. The host processes worker results separately from UI layout. Close/unsaved decisions are also dispatched independently of painting. Worker threads block on receive when idle.

Page selection changes the selected edit target immediately and invalidates the sheet only when navigation changes the output sheet. Selecting a cached page on the same sheet, including a repeated click, leaves the preview revision and texture IDs intact. Sheet rendering no longer depends on the selected page's thumbnail. Missing transformed thumbnails use a separate task after the current sheet is ready; identical cached pages are not uploaded twice. Background preview/thumbnail tasks do not toggle the toolbar, layout controls or global Working/Cancel status. Failed sheet renders retain the last bitmap and expose the existing retry/error state. The CPU host still constructs and rasterizes a complete offscreen UI frame for changed input; this is not a partial-frame renderer. Only a completed bitmap is presented through GDI, and runtime flicker remains unmeasured.

The preview caption occupies one stable row in ready, updating and failed states. Loading status is inline and retry remains inside that row; the last preview stays visible during regeneration. Plain-text page/sheet counts avoid an unsupported arrow glyph and use singular/plural forms. The bottom status panel also keeps a fixed height, with progress and cancellation in the same line. A static working label replaces the spinner. An in-memory egui regression checks unchanged sheet bounds across background-state transitions; it does not launch a native window or establish runtime presentation smoothness.

`assets/app-icon.svg` is the original printer artwork. The standard-library Python generator creates antialiased PNG/ICO assets at 16, 20, 24, 32, 40, 48, 64, 128 and 256 pixels. `build.rs` uses winresource and the Windows SDK resource compiler to embed icon group 1 plus product/version metadata into the application binary. The native host loads small/window and large/taskbar icons from that group. `inspect-pe.py` compares each linked icon payload against the source ICO without executing the binary. No icon file is needed next to the standalone EXE.

`design.rs` centralizes neutral light surfaces, graphite text, muted secondary text, one blue accent, pale-blue selection, borders and error roles. Body text is 15 points, headings 21 and action targets 34–36 points. Primary actions have hover feedback; disabled primary actions use the neutral button style. The original printer icon uses the same palette.

The empty workspace has one main Add files action. Populated layouts use a compact, virtualized page list with 100-point cards: thumbnail, page number, truncated filename and source-page/image caption. Move up/down stays beside the list; Remove lives in the Page inspector. Card labels do not intercept page-selection clicks. Selection opens the Page tab without changing document data or rerendering the same sheet. Reordering follows the selected page across sheet boundaries; removing the last page returns the inspector to Sheet setup.

The right inspector separates Sheet setup (paper, orientation, pages per sheet and color) from Page edits (left/right rotation, cropping, reset and remove). Margins/spacing and output quality expand on demand. The centered paper preview has a retained fixed-height status row and navigation below the sheet. Save PDF is the populated workspace's primary toolbar action; File keeps recipe actions. The layout-save status explicitly distinguishes recipes from PDF output. Settings centers the version/update controls and keeps supported-file/printing guidance in optional sections. Settings and long error details scroll within bounded windows; the unsaved-layout prompt emphasizes Keep editing. PrintHelper remains a document editor without a tray workflow. Headless component/whole-layout tests establish only their measured geometry and interaction cases; the complete interface has not been visually captured or natively verified under the no-GUI instruction.

## Drag and drop

egui-winit forwards native hovered/dropped file paths into RawInput. The workspace consumes dropped files once and shows a paint-only hint over the preview while files hover. Accepted paths become a foreground `ImportPaths` task, using the same transactional helper as the STA picker path without opening a picker. Decoding, source validation, thumbnails, 500-page/256-MiB budgets and cancellation stay on the MTA document worker. Import commits only after all thumbnails finish, including a final cancellation check. Missing local paths are rejected as a whole batch; directories are not expanded. Busy foreground actions, shutdown, a pending unsaved-layout choice and a full layout block new drops with feedback. Settings/source files are not written by a drop itself.

Page cards use click-and-drag with an egui payload containing source index and revision. A line marks the insertion slot, including row gaps and the space after the last page. The virtualized list's offset is included in hit testing. Mouse movement only updates feedback and scroll position; release commits one reorder through the existing project checkpoint, selecting the moved page and its sheet. Escape, release outside the list, lost focus, a stale revision or blocked editing cancels the operation. No-op drops create no Undo entry. Move up/down remains available as an alternative.

Edge scrolling requests a 16-ms animation deadline only while an active, valid page payload is inside an edge band and the offset can change. It stops at a limit, away from the band, on cancellation or release. No idle polling or document rendering is driven by hovering over insertion slots. The native host still suppresses all UI work while hidden; actual OS drag routing, edge-scroll feel, DPI and settling behavior remain pending a permitted GUI run.

File dialogs, PDF/image reads, thumbnails, sheet rendering, export, printing, settings writes and update HTTP/download work execute outside the UI thread. Native PDF operations run in an initialized MTA. Import/open is transactional: a failed/cancelled batch does not replace the active catalog/project. Catalog source cost is limited to 256 MiB, excluding opaque native renderer allocations. Deleting pages retains loaded sources for undo; New/Open releases the previous catalog. Application close cancels worker work; there is no tray or hidden background service.

`dialogs.rs` runs all four file-picker actions (input documents, open layout, save layout and export PDF destination) on a fresh, explicitly initialized STA thread. The bounded document worker waits for that short-lived thread and then resumes PDF work in its original MTA. Only paths cross the thread boundary. COM initialization is balanced by a thread-local RAII guard, including panic unwinding; thread/startup failures propagate to the normal error result. Calling rfd directly from the MTA worker previously failed its STA initialization and was silently reported as cancellation. A regression reproduces that exact HRESULT and verifies the isolated STA path without constructing or showing a picker. The COM threading rule is documented in [Microsoft's CoInitializeEx reference](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-coinitializeex).

## CPU rendering and presentation

`software.rs` wraps egui_software_backend 0.0.2 in a BGRA framebuffer. Shapes are tessellated and rasterized entirely on the CPU. Native presentation copies 0x00RRGGBB pixels to softbuffer 0.4.8, whose Windows implementation uses a GDI DIB and BitBlt. No OpenGL context, glutin, glow, wgpu or DirectX UI presenter is compiled into the Windows dependency graph. This does not disable the Windows compositor or make claims about internals of the OS PDF engine.

The library's internal mesh cache is disabled: an in-memory regression demonstrated that 0.0.2 reuses stale rasterized meshes when only texture contents change. The host still retains a complete last bitmap, so an unchanged OS exposure requires only presentation, without egui layout/tessellation/rasterization. Texture uploads/frees are retained if a prepared frame is suppressed by a hide/minimize transition; hidden worker updates remain in egui's texture manager until the next visible frame. Font-atlas retention, partial texture updates, frees, color order and framebuffer resizing are covered by headless tests.

`RepaintSchedule` coalesces invalidations and deadlines. It uses Wait or the next useful WaitUntil, never Poll. A queued OS redraw suppresses an already expired timer; hidden/minimized/occluded/suspended windows keep dirty state but provide no UI timer. Restore marks the scene dirty once. The framebuffer budget is 16 megapixels, and the native client-size maximum is 4000×4000 physical pixels. Oversized/transient invalid sizes suppress drawing instead of destroying application state. Only the CPU rasterizer dependency receives a development optimization override, as required by its upstream implementation.

Framework-level idle CPU, presentation latency, DPI compatibility, close decisions and restore behavior still require observation. `--render-diagnostics <new-file.json>` records aggregate UI/raster/present counts, exposure blits, suppressed redraws, wakeups and maximum per-stage times on exit. No GUI, self-capture or diagnostic launch was executed in this session; the runtime rendering/load gate remains incomplete. Source inspection, headless raster tests and a GPU-free PE import table do not establish measured idle load or visual correctness of the complete application.

## Update boundary

`updater.rs` supplies PrintHelper's product/version/repository, 200-MB limit and Windows GUI subsystem to the shared core. The core owns anonymous HTTPS release discovery, semantic precedence, canonical asset URLs, checksums/digests, PE validation and cancellable preparation. Startup checks retain the saved opt-out. The existing background worker returns a verified `Prepared` object to the UI; no installer starts until the user explicitly chooses Install and restart with a saved layout and no foreground work.

`rust-auto-updator` owns staging, parent-process verification/waiting, Windows replacement, rollback and restart. A 30-second startup-health window preserves rollback files until a first native presentation acknowledges healthy initialization. The product adapter translates the old flat `--finish-update` call into the shared transaction, preserving the published upgrade route. Settings, source documents and recipes are outside replacement and cleanup. No application/helper process or live updater download was executed in this audit.

The SHA-256 digest authenticates bytes relative to GitHub HTTPS metadata, not an independent publisher signature. Authenticode signing and release publication are not configured in this phase.


## Reusable updater

The existing background worker invokes the sibling `rust-auto-updator` core for release checks and cancellable verified downloads. A `Prepared` value, rather than an unchecked file path/digest tuple, crosses back to the UI. The host transfers it to an explicit install task only when the layout is saved and foreground work is finished. Shared handoff succeeds before requesting process exit; helper CLI routing occurs before normal app initialization. Legacy flat helpers are validated and migrated into the same shared transaction. Successful first presentation enables narrowly scoped cleanup.

## Interface language and appearance

`locales/*.json` embeds matching English, Russian, French, German, Spanish and Italian catalogs. English keys provide the complete fallback. Named placeholders keep paths and counts separate from prose; single-pass substitution preserves literal braces in user paths. Worker outcomes retain a `Message` template until display, so existing status/progress messages follow a language change. UI lookups use the selected UI-thread language; native file-dialog filters read the current process choice. Native Windows dialog controls retain the OS language, and raw technical diagnostics are not rewritten.

The existing serde-defaulted settings schema now stores language and a Light/Dark theme. Missing fields in older settings default to English and Light while retaining startup-update preferences. Appearance controls live above Updates in the existing Settings window and save through the document worker. Stable window IDs preserve placement when localized titles change. `design::Palette` supplies both complete palettes, including custom page cards, drop hints and preview surfaces; document paper remains white. Changes reapply the style once and use ordinary event-driven invalidation. The renderer, retained bitmap, hidden-window policy and background-work boundaries are unchanged.
